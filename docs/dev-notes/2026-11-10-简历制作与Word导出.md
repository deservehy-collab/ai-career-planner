# 简历制作：纯代码生成 A4 简历 + Word / PDF 导出

日期：2026-11-10
范围：新增 `/resume` 页面、简历数据层、`POST /api/resume/docx`；不改六表档案结构、不写业务数据、不动 `.env`、不提交。

## 阶段 1：简历数据模型与自动带入

### 改了什么

- 新增 `web/src/utils/resume.js`：内容模型分 8 段（基本信息、求职意向、教育、技能、实习、项目、校园、证书与自评）。
- 自动带入只搬档案里已经存在的事实：
  - `target_job` → 求职意向；`profile_snapshot` 的学校/专业/学历/时间/年级/GPA → 教育；
  - `current_skills` 按等级分组，自述技能归入「其他」并去重；
  - 成长记录里的项目事件按时间新→旧，跳过 `voided_event_indices`；没有成长记录时用**已完成**的实战项目兜底；最多 6 条，按标题去重。
  - 姓名、电话、邮箱、学校等没有来源的字段保持空白，纸面显示占位文字，不编造。
- `normalizeResume` 在导出/打印前统一去空：全空条目、空技能组、空行一律不出现；打印 HTML 做转义，只有第二页有内容时才强制分页。
- 草稿键为 `career-agent:resume:{userId}:{planId}`，按账号 + 档案隔离，350ms 防抖自动保存。

### 验证

- `web/src/utils/__tests__/resume.spec.js` 11 条：自动带入不编造、技能分组去重、项目来源优先级、统计六项必填、空结构、归一化、打印 HTML 转义与分页条件。

### 风险

- 学校/公司/奖项没有结构化来源，仍要用户手填；这是产品口径，不是漏做。
- 草稿只在本机，换浏览器看不到；后续若要多端同步，需要新表（本次未获批，不做）。

## 阶段 2：简历工作台页面

### 改了什么

- 新增 `web/src/views/ResumeView.vue`：
  - 顶部工具栏：来源档案选择、已填写/必填待补读数、打印 / 存 PDF、导出 Word；
  - 左侧两页 A4 预览（96dpi 794×1123，按容器宽度缩放；内容超出给出续页提示）；
  - 右侧 8 段手风琴编辑；窄屏改为「编辑 / 预览」切换；
  - 切换档案时同时核对账号、档案 id 与 `plans.epoch`，迟到的旧响应不覆盖新档案；
  - 没有档案时给「去新建档案」入口，而不是空白简历。
- 路由 `/resume` 放在 `/status` 之前；侧边栏「简历制作」位于「成长记录」与「系统状态」之间；宽屏容器放宽到 1520px。
- 样式全部追加在 `web/src/styles/main.css` 的 `rm-*` 段：纸面用宋体、章节细线、编号列表；屏幕侧沿用全站变量与发丝线，不新增主题色。

### 验证

- `web/src/views/__tests__/ResumeView.spec.js` 6 条：自动带入、编辑同步、必填读数、打印/导出调用、草稿按档案隔离、无档案空态、窄屏切换。
- 浏览器验收（独立测试账号 + 独立档案，未触真实用户数据）：
  - 1440 宽：双栏 `648px + 432px`，编辑栏 sticky，A4 预览无横向溢出；
  - 390 宽：默认编辑页，切「预览」后只显示纸面，无横向溢出；
  - 真实输入姓名/电话后纸面同步、350ms 后落本机草稿；刷新后显示「继续编辑本机草稿」且内容还在。

### 风险

- 两页 A4 在手机上按比例缩到约 0.4，文字偏小；这是整页预览的固有代价，编辑仍在独立页面完成。
- 运行中的 8000 进程是本次改动前启动的，未自动加载新路由；验收时另起临时 8010 确认，正式使用前需重启后端。

## 阶段 3：Word 导出（零新依赖）

### 改了什么

- 新增 `backend/resume_docx.py`：用标准库 `zipfile` + OOXML 手写 DOCX，不新增依赖。
  - A4：`11906 × 16838` twips，左右边距 964、上下 567；
  - 姓名黑体 19pt、章节标题黑体 12pt 带下边框、正文宋体 9.5pt；条目单位/角色/时间一行，时间右对齐；编号列表悬挂缩进；
  - 第一页：姓名/联系方式/求职意向/教育/技能/实习；第二页：项目/校园/证书/自评；第二页有内容才插分页符。
- 新增 `backend/resume_api.py`：`POST /api/resume/docx`，登录必需；字段长度有上限；空简历返回 422 和可操作文案。
- `backend/app.py` 注册路由（`/api` 前缀），接口表补一行。
- 前端 `client.js` 增加 blob 响应，`endpoints.js` 增加 `exportResumeDocx`，`download.js` 用 object URL 触发下载。

### 验证

- `backend/tests/test_resume_docx.py` 7 条：zip/XML 结构、正文内容、字体与 A4 尺寸、空简历 422、超长条目 422、未登录 401、分页符只在第二页有内容时出现。
- 临时 8010 进程真实请求：`200`、正确 MIME、1228 字节、文件头 `PK`；用本机 python-docx 打开为 A4 210×297mm、段落可读。
- `tests` + `backend/tests` 全量：**674 passed, 2 xfailed**；前端 21 文件 **147 passed**；`npm run build` 通过。
- 顺手修了一处测试隔离缺陷：`backend/tests/test_node_progress.py` 清理时把 conftest 的全局鉴权覆盖删掉，改为恢复原值；否则排在它后面的新路由测试会 401。

### 风险

- DOCX 是固定版式，不跟随 Word 里的用户改页边距；超长内容会自然续页，但不会自动压缩字号。
- 参考简历里的照片未做：照片需要上传与存储，属于未批准方向；当前版式无照片列。

## 阶段 4：去掉打印，改为直接下载 PDF / Word

### 改了什么

- 按“不需要打印，只要能导出电子档”的要求，删掉整个浏览器打印链路：`resumeToPrintHtml`、各段打印 HTML 拼装、`openResumePrint`、工具栏「打印 / 存 PDF」按钮；`web/src/utils/resume.js` 只保留数据模型、自动带入、归一化和文件名。
- 新增 `backend/resume_pdf.py`：服务端把简历数据渲染成 A4 HTML（`html.escape` 转义），再调本机 Chrome / Edge 的 `--headless=new --no-pdf-header-footer --print-to-pdf` 生成 PDF，不新增依赖。
  - 查找顺序：`RESUME_PDF_BROWSER` → PATH 里的 chrome/chromium/msedge → Program Files 常见安装路径；找不到返回 503 并提示可先导出 Word。
  - 用独立 `--user-data-dir` 临时目录，45 秒超时，结束即清理；只有用户真填过的内容才上纸。
- `backend/resume_api.py` 新增 `POST /api/resume/pdf`（登录必需，空简历 422），请求模型改名为 `ResumeExportRequest` 供两个导出接口共用。
- 前端工具栏改为两个按钮：「导出 PDF」（次要）与「导出 Word」（主要）；`endpoints.js` 增加 `exportResumePdf`，下载仍走 `saveBlob`。
- 删掉编辑区页脚那句「草稿只保存在这台浏览器；导出与打印不写业务数据。」，只留「重新从档案带入」。
- 修了一个实际会挡住导出的缺陷：`:disabled="!canExport || exporting"` 里 `exporting` 初始是空串，Vue 会把空串渲染成 disabled，导致按钮一直不可点；改成 `!!exporting`。

### 验证

- `backend/tests/test_resume_pdf.py` 7 条：HTML 转义、空栏目不上纸、分页只在第二页有内容时出现、不编造联系方式、缺浏览器 503、空简历 422、真实渲染（有浏览器时）断言 `%PDF`、A4 MediaBox 594–597 × 840–844、页数上限 2。
- 前端 `resume.spec.js` 收敛为 8 条（打印 HTML 用例随功能一起删除）；`ResumeView.spec.js` 新增导出 2 条：PDF/Word 各自下载且文件名正确、503 时报错显示在 `.rm-alert` 且不触发下载。
- 临时 8010 进程真实请求（独立探针账号、独立档案，验收后删除）：`/api/resume/docx` → `200`、1517 字节、`PK`；`/api/resume/pdf` → `200`、`application/pdf`、97132 字节、`%PDF`，解压流里页数 2、A4 尺寸。
- 全量：后端 `pytest tests backend/tests` **681 passed, 2 xfailed**；前端 21 文件 **145 passed**；`npm run build` 通过。
- 浏览器验收：工具栏只剩 `[导出 PDF, 导出 Word]` 两个动作，页面已无任何“打印”文案，页脚只剩「重新从档案带入」。

### 风险

- PDF 依赖本机浏览器：部署到没有 Chrome/Edge 的机器会返回 503，只能用 Word；这是为零新依赖做的取舍。
- 用户反馈“导不出 Word”的实际原因是 8000 端口跑的是改动前的旧进程（15:54 启动，代码 21:47 才写入），没有 `resume` 路由，请求直接 404；重启后端后实测 `docx 200 / 1249 字节 / PK`、`pdf 200 / 41121 字节 / %PDF`。
- `czb.bat` 检测到 8000 已在监听会跳过启动后端，所以改完后端代码后重跑脚本不会加载新代码，必须先关掉 backend-8000 窗口再启动。脚本本身用的 `.venv` 和启动命令都是对的，无需修改。

## 阶段 5：按参考件逐像素对齐（PDF / Word / 预览）

### 改了什么

- 版式基准改为「参考简历 PDF 量出来的几何」：A4 边距 20 / 14 / 13.7 mm，姓名 20pt，小节标题 12pt 加粗 + 通栏细线，正文 10pt、行距固定 15.6pt，联系方式与求职意向各两行四列，条目行“时间—单位—角色”三段式。
- `backend/resume_pdf.py`：重写导出 CSS（`.sec` / `.sec>h2` / `.headline*` / `.flow--intent`）。小节标题下边框、标题到首条的间距、条目标题三列列宽、正文行距全部按参考件实测值；页面不再插强制分页。
- `backend/resume_docx.py`：
  - 修掉条目行三个制表符被写成字面量 `\t` 的问题（此前 Word 里单位/角色挤在一起），改为真实 `<w:tab/>`；
  - 姓名段改 `lineRule="exact" 24pt`、`after=16.4pt`；小节标题 `before/after`、细线 `w:space`、条目首行 `before`、行内 `exact 12.5pt` 逐项按 Word COM 渲染结果回调；
  - 列位：条目角色 tab 7768、学历 tab 6022；正文行距固定 312 twips。
- `web/src/views/ResumeView.vue` + `main.css`：纸面预览顺序改为与导出/参考一致（求职意向 → 教育 → 工作/项目/校园/研究 → 技能证书 → 自我评价），纸张字号 26.7px、小节 18px 间距、条目标题三列 322px 与学历列 401px，编号由文本前缀生成，导出与预览不再各排一套。

### 验证

- 同一份参考内容分别渲染 PDF 与 Word，再用 Word COM 把 DOCX 转回 PDF，逐行取文字 y 坐标对照（110dpi 下换算 pt）：
  - 页内文字与 PDF 基准误差 ≤ 1.3pt，小节细线位置 `168.0 / 245.2 / 381.0 / 697.7pt`，与 PDF 基准 `168.0 / 245.2 / 381.8 / 697.5pt` 对齐；
  - 姓名→联系方式、意向两行、学历/角色列、条目首条、正文行距均与基准一致。
- 后端 `pytest tests backend/tests`：**684 passed, 2 xfailed**；`-k resume` 17 passed；前端 `vitest run` 21 文件 **145 passed**。
- 浏览器验收用 Playwright + 路由拦截的假数据（假账号 `verify-user`、假档案 `plan-verify`、假草稿 key），未登录真实账号、未读写真实草稿：
  - 1440 宽双栏、1024 宽切「预览」页签、480 宽单栏预览均无横向溢出；
  - 纸张栏目顺序、细线、四列意向、三列条目与导出件一致，2 页共 1894px。

### 风险

- Chrome（PDF 导出）与 Word 的行距取整方向不同，两页文档的断页位置会差一行；各自页内版式一致，未强行统一分页。
- 参考件里姓名右上角有照片，本次样例没有照片所以该区域留白；照片仍按“只有用户上传才上纸”的规则处理。
- 参考件的教育条目带 `*` 前缀、工作条目带“工作职责及业绩：”引语，属该模板的填写约定，当前数据模型没有这两个字段，未伪造。
