# AI 面试陪练：按当前档案出题 + 参考要点

日期：2026-11-12
范围：新增左侧导航 `/interview` 页面与 `POST /api/interview/questions`；不改六表与档案结构、不写任何业务数据、不动 `.env`、未提交。

## 阶段 1：后端出题接口（只读）

### 改了什么

- 新增 `backend/interview.py`：
  - 证据只从两处取：档案的 `target_job` / `jd_text`（截断 3000 字）/ `profile_snapshot` / `current_skills`，以及前端传来的本机简历草稿。
  - 简历只提取技能、经历条目（时间｜标题｜角色：要点）、自评、证书、语言；**电话、邮箱等联系方式不进入提示词**。
  - 没有草稿时退回档案画像与能力表，响应里用 `sources.source` 区分来源，前端据此显示「依据：简历草稿 / 档案资料」。
  - 单次最多 10 条材料、20 项技能；输出 3–8 题（默认要求 6 题）。
  - 通道沿用 `agents.llm.get_channel()`：本地 Ollama 用 `/api/chat`，云端走 OpenAI 兼容 `/chat/completions`（429 重试一次、401/403 标记鉴权失败），不新增依赖。
  - 解析容错：允许 markdown 代码围栏、前后解释文字、`{"questions": [...]}` 包装；分类白名单为 技术 / 项目 / 动机 / 反问，要点最多 4 条；有效题少于 3 条视为格式失败。
- **反问题改为确定性生成**：小模型会把「技术题」错标成「反问」，因此模型产出的反问一律丢弃，统一追加一条「关于<目标岗位>，入职后前三个月团队最看重什么？」，保证 6 题的分类顺序稳定。
- `POST /api/interview/questions`：档案不存在 404、没有目标岗位 422、模型不可用 503、格式不达标 502；错误文案都是人话，不含堆栈与路径。响应 `{target_job, channel, model, questions, sources}`，不落库。

### 验证

- `backend/tests/test_interview_questions.py` 12 条：材料提取排除联系方式、档案兜底、JD 截断、围栏 JSON 解析、包装对象与坏条目丢弃、垃圾输出拒绝、上限 8 题、反问替换与补位、接口 200 / 404 / 503 / 502。
- 真实模型（qwen2.5:3b，假数据脚本，未读数据库）：连续跑出 6 题，分类顺序 技术、技术、项目、项目、动机、反问，反问为确定性文案。

### 风险

- 本地 3B 模型出的题深浅不稳，复杂岗位偶尔只到「概念确认」层；这是模型能力上限，不是解析问题。
- 出题耗时 20–60 秒（本地），页面只能等；没有做排队或缓存。

## 阶段 2：前端面试陪练页与左侧入口

### 改了什么

- 新增 `web/src/views/InterviewView.vue` 与路由 `/interview`（`meta.wide`），左侧导航「面试陪练」放在「简历制作」之后。
- 页面只做三件事：读当前档案（`GET /api/plans/{id}`）、读本机简历草稿（`career-agent:resume:{userId}:{planId}`）、调出题接口。
- 状态齐全：无档案时给「去我的档案」入口；有档案未出题时说明题目构成并提示有无 JD 原文；生成中显示骨架屏与「本地模型通常需要 20–60 秒」；失败显示后端文案 + 重试；生成后按 技术题 / 项目深挖 / 动机与匹配 / 反问面试官 分组，参考要点默认收起。
- 切换档案时同时核对 `plans.activeId` 与 `plans.epoch`，迟到的旧响应不会写进新档案；离开页面后丢弃挂起请求。
- 页脚明确：题目与要点不写入档案、不进成长记录。

### 验证

- `web/src/views/__tests__/InterviewView.spec.js` 5 条：无档案入口与按钮禁用、空态不自动请求、请求带档案与本机草稿并按四类展示、要点折叠展开、失败重试。
- 浏览器验收（独立 mock 数据，未触真实用户数据）：
  - 1440 宽双列卡片、900 宽单列、390 宽单列且无横向溢出；
  - 空态、生成后列表、展开参考要点三种状态截图均已核对；
  - 左侧导航出现「面试陪练」，页面标题与说明可读。

### 风险

- 生成结果按账号 + 档案缓存在本机（见阶段 3），换浏览器看不到；要留档仍需自己复制。
- 简历草稿按账号 + 档案保存在 localStorage，换浏览器看不到，出题材料会退回档案资料。

## 阶段 3：删掉页面小字 + 切页不丢题

### 改了什么

- 删除页面上的说明性小字：顶部引导段、空态的两段解释、结果上方的「依据：…」、每道题的「为什么问」、页脚提示；空态只保留标题，出错与生成中的状态文案保留（它们是操作反馈，不是页面介绍）。
- 新增 `web/src/stores/interview.js`：题目结果与进行中的请求都放在 store 里，按「账号 + 档案」分开。
  - SPA 内切走再回来：题目还在，进行中的请求继续跑，回来后先显示生成中、完成即出题，且不会重复请求；
  - 成功后写本机 `career-agent:interview:{userId}:{planId}`，刷新后仍能恢复；
  - 失败只记在当前档案下，重试成功后清除。
- 页面本身不再维护请求序号与「已卸载」标记，也不再额外请求档案详情（那只是为了显示 JD 小字）。

### 验证

- `InterviewView.spec.js` 增至 7 条：新增「切走再回来题目还在且不重复出题」「刷新后从本机缓存恢复」；空态断言改为止于标题、无引导小字。
- 浏览器验收（CDP + 8000 未被占用时改用请求拦截，独立 mock 数据）：
  - 生成后 6 张卡片；侧边栏跳去概览再回面试陪练，6 张卡片仍在，请求数不增加；
  - 刷新页面后从本机缓存恢复 6 张卡片，不发请求；
  - 把 mock 响应延迟 2.5 秒，点生成后立刻切到概览、再切回：页面显示生成中，完成后出现 6 张卡片，全程只有 1 次请求。
- 前端全量 22 文件 / 152 tests 通过，`npm run build` 通过。

### 风险

- 生成中直接刷新或关闭标签页会中断请求（前端无法在文档卸载后保住连接）；本题不落库，刷新后也没有可恢复的结果。要彻底解决需要后端异步任务，本次未做。

## 阶段 5：修「模型返回的内容不是 JSON」

### 根因

- 本地 `qwen2.5:3b` 偶发写坏 JSON：实测同一份材料 8 次里 1 次，模型在 `follow_up` 冒号后多写一个引号（`"follow_up":""你……"`），整份解析失败 → 502。
- 排除项：输出未被截断（`done_reason=stop`、约 400/1400 token）；通道从 11-10 起就是本地；后端进程 11-13 08:47 启动，跑的是当前代码。短/长材料、有无 JD 共 19 次调用只错这 1 次。

### 改了什么

- `backend/interview.py`：本地请求带 `format=QUESTION_SCHEMA`（Ollama 结构化输出，数组 + 必填字段 + 6 条）。
  - 先试过 `format="json"`，实测更糟：3B 模型只吐单个对象，6/6 解析失败，已弃用。
- `generate_questions`：输出不是 JSON 时自动再采样一次（`MODEL_ATTEMPTS=2`），仍失败才报 502。

### 验证

- 新增 3 条测试：payload 带 schema、坏输出自动重试且第二次成功、两次都坏才抛错。`backend/tests` 145 passed + 3 subtests。
- 实测同一份材料：schema 9/9 出 6 题（修前 1/8 失败）；完整链路带重试拿到 6 题。

### 未做

- 后端需要重启才加载新代码（当前 8000 进程是改前启动的）。
- 未加入「把模型原文写日志」，故障复发时仍只能靠统计复现。
