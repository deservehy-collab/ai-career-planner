## 阶段 A · 病灶定位（只诊断，未改码）

**做了什么**

把 `web/src/styles/main.css`（改动前 6029 行）里的页面版式按前缀摊开，确认"不行"具体指什么：
同一个应用里有**七套互不相干的版面方言**。

| 页面 | 方言 | 版式 |
| - | - | - |
| 概览 | `ov-*` | 大 hero + 双栏 grid |
| 我的档案 | `grid grid-2` | 等分卡片阵 |

只有最后一套是他点头认可的。所以病灶不是"某一页做得差"，而是**没有主线**：
每页各自决定报头怎么排、内容分几栏、次要信息放哪。

**选型**：给出 A/B/C 三个骨架草图，他选 **A**（报头 + 单列排队 + 右侧细栏）。
落法约定（当时一起说的）：A 铺全站；分析页局部借 C 的右栏放"依据"；成长记录页用 A 的

4. **`.pg-index` 在 ≤1200 会转成"进度 + 读数"横排摘要**，那是登记册索引的形状；概览/分析的细栏

   登记册那套保持原样（像素对照证明没变）。
5. 上一轮记的「`.reg-ruler > div` 疑似写错选择器」**不成立**：`.reg-facts > div` 本来就是 flex，

## 阶段 D · 概览返工成「一屏看完的四站路线」

他把阶段 C 的概览否了：「不要那种一块块的工作台，也不要下拉的整齐的页面」——
概览要一眼看懂怎么用、能点进各页、还要生动一点。于是这一轮的硬指标改成
**首屏装得下**：`scrollHeight ≤ 视口高`，三档本地画像 × 四档视口逐个量。

**做了什么**

- 五块工作台 → **一条四站路线**：虚线脊柱从第 1 站画到第 4 站，站点 = 图标 + 标题 + 一行说明 +
  去处链接；只有亮着的那一站展开成「这一步现在做什么」+ 全页唯一的主按钮 + 一个次级文字链接。
  四站顺序就是使用顺序，读一遍就知道怎么用。
- 「第 2 站里跑的是七个步骤」带：7 个色片按四色族上色（`:title` 给完整展示名与职责，不给假进度），
  旁边四个产出锚点直接跳 `/analyze#card-requirements/-gaps/-learning/-projects`，下面一行色族图例。
- 细栏三块：档案四行读数 / 画像还缺（压成一行）/ 开始之前（五条须知，第一条带 `/status` 去处）。
  旧的 `.ov-brief` 和「另外两页」分组删掉——侧栏已经指过路，同一件事不摆两遍。
- 类名换代：退掉 `.ov-hero / .ov-start / .ov-entry / .ov-spine / .ov-station / .card--next / .loose-note`，
  换成 `.ov-route / .ov-stop* / .ov-chain* / .ov-tick* / .pg-rail-notes / .pg-rail-warn`。
  唯一的"动"是亮着那站的序号牌在呼吸（`@keyframes ov-here`，`prefers-reduced-motion` 下不跑）。
- 两处为「一屏」让路的具体改动：`retrieval` 节点在色片上用四字短名「资料整理」（「招聘原文整理」会把
  整带挤成两行）；下一步 desc 各压到一行内，砍掉的时长口径没丢——须知里仍写着「一次规划几十秒到几分钟」。
- 矮窗口（宽 >900 且高 ≤780）另收一档：站距 `8/9 → 4/5`、须知行距 `5 → 3`、色带上下留白降一档。
- 测试 `OverviewView.spec.js` 6 → 9 例：四站编号与去处、三档各亮在哪一站、全页只有一个主按钮、
  七色片 + 图例 + 四产出、细栏一行「还缺」两种状态、整页不发请求。

**验证命令与结果**

| 命令 | 结果 |
| - | - |
| `cd web && npx vitest run` | **10 files / 59 passed**（上一轮 58，本轮 +1，0 失败） |
| `cd web && npm run build` | ✓ built in **1.11s** |
| 一次性 vite(5175) + 假接口 + headless Chrome CDP | 3 档画像 × 4 档视口共 12 张 + `/tasks` 对照，`Temp/aicareer-ui-round/shots/final-*.png` |

| 横向溢出 | 12 档全部 `scrollWidth == innerWidth`，`overflowX=false` |
| 「学习与项目」像素对照 | md5 `d29de8b6…` 与本轮起点逐张一致 —— 这轮没碰它 |

**发现的问题（都是实测）**

1. **同特异性下 CSS 后面的赢**：矮窗口那段最初插在 `.ov-chain` 之后，而 `.pg-rail-notes` 基线写在更下面，
   于是须知行距的覆盖一句没生效（`doc` 死活停在 725）。整段挪到概览区末尾才落到 720。
2. **首屏的下限不一定是主栏**：1280×720 时主栏底只有 670，把页面顶出滚动条的是 699 的细栏。
   只量主栏会误判"已经装下了"。
3. `.app-shell { min-height: 100vh }` 让 `document.scrollHeight` 永远 ≥ 视口高，所以"装得下"要看
   内容底 / 滚动元素，不能只看 `doc`。
4. 七个色片在 686px 主栏里只差 10px 就换行（片宽合计 613 + 6 段间距 24 = 637 > 636）——
   短名一处就够，不必再缩字号。
5. 旧「画像还缺」把 store 的「未填写专业」逐行列成 `dt`，右列再写「未填」，同一件事说两遍，
   还把细栏顶到 134px。现在一行 `专业 / 年级 / 自述技能`，填齐时只说「没有缺项」。

**本轮没做（等他定）**

- **1000×800 这类 ≤1200 的宽度仍然要拉页**：骨架在 ≤1200 把细栏折到页尾（阶段 C 定的），
  概览因此变成两屏。要在这种宽度也不拉页，只能让细栏折到报头下面或收进抽屉——这是他欠一次选择的地方。
- 岗位分析 / 成长记录 / 系统状态 / 我的档案四页的布局草图已给，等他逐页点名（`分析 B / 成长 A / …`）。
- 「一屏」现在是概览的硬约束：以后往这页加东西，先看 `scrollHeight`，再加内容。

## 第二轮：全站文案清理（2026-11-06）

用户反馈「每个页面都会出现一些程序员才需要看的几行字」，要求逐页看着改。本轮只改文案、枚举映射与错误提示，
不动接口、存储格式、路由和真实数据。

**原则**

- 用户页只回答三件事：这是什么、现在该做什么、出问题怎么办。
- 后端里的东西不上用户页：服务名、模型 ID、base_url、文件路径、数据库编号、原始枚举键、JSON 原文。
- 排障细节集中在「系统状态」页，并收进「配置详情（排查用）」「模型与连接详情（排查用）」折叠块；
  用户不展开就只看到「本机 / 云端」「可用 / 需要处理」。

**统一替换**（按出现位置逐处改，不是全局搜索替换）

| 原来 | 改成 |
| - | - |
| 后端 / 接口 / API | 服务 / 这台电脑上的分析 |
| 模型通道 / 通道 | AI 运行方式 |
| 模型名（qwen2.5:3b 等） | 本机 AI / 云端 AI，具体名字进折叠块 |
| 落盘 / 写入成长历史 | 保存 / 记进成长记录 |
| Agent / 节点 / 流水线 | 步骤 / 规划流程 |
| 模型推断 / 模型补充 | AI 推断 / AI 补充 |
| 招聘原文 | 依据原句 / 你的招聘要求 |
| 前置门禁 | 前置检查 |
| localStorage / 浏览器存储 | 这台设备 / 这台电脑 |

  旧数据与纯文本都能显示。清空清单的备份不再显示文件名，只说「已经备份到这台电脑的数据文件夹里」。
  没填证据的任务直接写明「这项任务不会记进成长记录」。
