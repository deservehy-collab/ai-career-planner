# 知识库全学科补齐：开发留痕

日期：2026-11-10
范围：16 个学科方向的岗位/技能/项目数据、领域白名单、消费层口径、golden 用例与测试哨兵。

## 阶段 1：领域注册与校验口径

- 改了什么：`agents/job_catalog.py` 的 `VALID_DOMAINS` 从 6 个扩到 16 个（新增 human-resources、design、healthcare、electronics、mechanical-civil、media-language、legal-public、agriculture-environment、sports、bio-chemical）；`scripts/validate_knowledge.py` 同步白名单，并保留“每个领域至少 3 个项目、整体至少两档难度、技能名跨岗位全局唯一”的口径。
- 验证：`python scripts/validate_knowledge.py` 退出码 0，技能、项目、岗位画像交叉引用全部通过。
- 风险：领域是白名单而非自由字符串，新增方向必须同时改代码与校验脚本，否则岗位加载会直接报错。
- 下一步：按学科方向补数据。

## 阶段 2：10 个方向的岗位、技能底座与项目

- 改了什么：新增 10 个知识库文件方向、20 个岗位画像（人力资源/设计、医药护理、电子电气、机械土木、传媒外语、法学公共、农林环境、体育、生化检验）、对应技能底座与 30 个项目模板；每个岗位保留文件头来源说明（公开标准/法规整理 + JD 汇总，注明检索日期），岗位技能全部在技能库有四级 guide。
- 验证：`validate_knowledge.py` 通过；`SkillKnowledgeBase` 计数 237 与岗位技能并集一致；别名冒烟（法务助理、体育教师、翻译、化学分析员、环境检测员等）全部解析到预期 job_id。
- 风险：跨方向复用技能（Excel、内容策划、文案写作、实验室质量控制）会让“按技能反推领域”不再唯一，这是数据事实，不是缺陷；`domain_for_skills` 按设计返回 None。
- 下一步：对齐消费层与测试。

## 阶段 3：消费层口径与测试对齐

- 改了什么：`tests/test_job_catalog.py` 改用运营独有技能判断领域、补充“字面名优先于别名”（成本控制）；`tests/test_jd_match.py`、`test_job_profile.py`、`test_source_attribution.py`、`test_golden_cases.py`、`test_multi_domain_projects.py` 的“陌生岗位”哨兵由护士/电气工程师/内容策划改为仍未收录的宠物美容师/品酒师；`golden/cases.yaml` 的两条长尾用例同步换岗并改名。
- 验证：`pytest tests -q` 554 passed / 2 xfailed；24 条 golden 用例的 `expect.domain` 与目录解析结果 0 不匹配；后端重启后 `/api/ping` 200，`_knowledge_status` 报告 237 技能 / 66 项目 / 32 岗位 / 490 条证据 / 64 个来源。
- 风险：护士、电气工程师已从“陌生长尾”变成知识库岗位，任何仍把它们当未知岗位的旧脚本或文档都会得到相反结论。
- 下一步：无；如需继续扩面，按同一模板补方向并同步白名单与 golden 用例。
