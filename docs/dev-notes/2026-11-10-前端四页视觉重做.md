# 前端四页视觉重做：档案、任务、助手与顶栏

日期：2026-11-10
范围：`web/src/views/HomeView.vue`、`TasksView.vue`、`AssistantView.vue`、`App.vue`、
`web/src/styles/main.css`；不动后端、不动真实数据、不提交。

## 阶段 1：删掉「当前档案」横条

### 改了什么

- `App.vue` 不再挂 `PlanSelector`，删除 `web/src/components/PlanSelector.vue`。
  这条横条只在 `/home` 出现，内容（当前档案下拉 + 管理档案）与页面本身重复，
  「管理档案」还指回同一个页面。
- 删除前 grep 确认没有其它引用与测试选择器依赖。

### 验证

- `npm test`、`npm run build` 全绿；`/home` 首屏不再出现 `.plan-bar`。

### 风险

- 无数据影响：选择档案仍在「我的档案」列表里切换，`/tasks` 等页从 `plans.activeId` 取上下文。

## 阶段 2：我的档案降密度、卡片化

### 改了什么

- 档案头改为浅色渐变卡：`当前目标` 小标 + 目标岗位 + 专业/年级 + 完成度条 + 操作，
  右侧单列「能力数 + 更新时间」，窄屏折到下方。
- 画像字段与当前档案能力表各收进一张白卡，两列并排；`data--skills` 收紧行高。
- 档案列表从表格行改为卡片网格（`auto-fill, minmax(280px, 1fr)`）：
  左侧 3px 书脊（当前档案用品牌渐变）、标题 + 徽标、岗位与计数一行、底部更新时间与操作。
- 删除确认面板仍留在卡片内，文案与级联说明未变。

### 验证

- `HomeView.spec.js` 13 条契约类名与文案全部保留，125 条前端测试通过。
- Chrome CDP 截图：1440×900 三卡一行；390 宽单列，无横向溢出。

### 风险

- 卡片网格依赖 `auto-fill`，档案多于 3 份时按列数换行；未改分页接口。

## 阶段 3：学习与项目改书签任务墙

- 一轮全部完成时墙上给一句「这一轮的书签都收进下方『已完成』了」。
- 左栏去掉「结局」读数与表头行，进度块只保留待完成、轮次、目标岗位、清单状态与按轮次筛选。

### 验证

  `.reg-sheet` 等选择器未变，一键完成、弹层、补凭证路径全部通过。
- 截图验证：4 张待办卡两列；展开已完成册后单卡撑满整册（`auto-fit`）。

### 风险

## 阶段 4：AI 助手页视觉提升

### 改了什么

- 页头补 `AI 职业助手` 小标、主张句与一句副标题（说明对话不改档案与成长记录）。
- 空态改为品牌标记 + 标题 + 说明 + 四张带序号的起点卡 + Enter 提示；去掉假头像假历史。
- 对话容器加圆角与阴影，输入区改浅渐变、更大圆角。

     把标题和说明顶出视野；

     四张起点卡不再被固定高度裁进内层滚动区。

### 验证

- 1440×900 与 390×844 截图：桌面副标题一行不孤字；手机首屏完整呈现
  标记、标题、说明、四张卡与输入框；控制台无报错。

### 风险

## 阶段 5：岗位分析页改诊断台式版式

用户第 5 条：岗位分析页的布局格式有问题，要和其他页面明显不同。

### 改了什么

- 整页换成「诊断台」一套独立版式，不再复用其他页的圆角渐变卡片：
  - 页头改深墨蓝底 + 青色网格纹，左侧小标 + 宋体大标题 + 说明，
    右侧「当前档案」规格牌（档案名、目标岗位、依据说明）。
  - 输入区改成两张编号纸页：`01 个人画像` / `02 招聘原文`，
    方角、1px 细线、无阴影；招聘原文页头右侧保留依据标签。
    画像表单在图外的 `.an-sheet` 里强制两列，避免单列把纸页拉得过长。
  - 结果区左侧流程轨改深色仪表轨（浅色节点字、细蓝滚动条），
    右侧报告栏加 `ANALYSIS REPORT` 小标 + 宋体岗位名 + 四态印章
    （排队中 / 分析中 / 已完成 / 未完成，只映射后端 `analysis.status`）。
  - 报告内卡片统一 4px 方角、细线边框、浅灰表头，去掉柔和阴影。
- 保留全部交互节点与文案：停止分析 / 确认删除 / 开始新档案 / 清空结果 /
  依据横幅 / 预览提示 / 各结果卡片均未改绑定。
- 响应式：≤1100px 输入区单列；≤980px 页头与工作区单列、流程轨回落为静态；
  ≤640px 纸页缩小内边距，招聘原文页头的依据标签换行独占一行。

### 验证

- `AnalyzeView.spec.js` 10 条停止流程测试全过（只锁 `.an-stop*` 选择器）。
- 1440×1000 / 390×844 截图：
  - 空态两张纸页高度接近（815px vs 716px），整页一屏内收口；
  - 手机端招聘原文页头不再被标签挤成三行窄字；
  - 结果态深色轨、报告印章、方角卡片均正常，控制台 0 报错；
  - 结果态整页桌面 5989px、手机 9424px，逐屏抽查无溢出。

### 风险

- 只改模板结构与 CSS，未动 store、接口、轮询与任何后端字段。
- 结果页右栏宽度与旧 `.layout-rail` 一致（252px→264px），
  岗位要求表在原宽度下本就偏挤，本次未改表格列宽。

## 阶段 6：任务清单改横向任务栏 + 「咻」离场动画

### 改了什么

- 待办从两列书签墙改为**一列横向任务行**（`.task-list` / `.reg-row.task-row`）：
  左侧彩色状态圆点（学习=青、项目=玫红），中间编号 + 标题 + 类型徽标，
  下一行技能胶囊、预计周数/项目难度、轮次与「待完成」状态，右侧「标记完成 / 附凭证·心得」。
- 难度/预计周数只从**最新一轮计划明细**读取（项目取 `difficulty`，学习取
  `estimated_weeks`）；旧轮次没有明细就不显示，不按标题猜一个。
- 「标记完成」成功后不再立即刷新清单：先给该行挂 `is-leaving`，播放
  400ms `task-whoosh`（标题划掉、圆点转绿、缩小淡出并向左滑走），动画结束后
  才重新拉清单；接口失败时不播动画，错误仍落在清单上。
- 系统开启「减少动态效果」时跳过等待，直接刷新，不为动画拖慢操作；
  切页时清掉离场计时器，避免回来时多拉一次清单。
- 左栏进度块换成真实进度条 + `百分比 完成`，按当前筛选轮次的已完成/总数计算，
  无任务时按 0%，不出现 NaN；`role="progressbar"` 同步 `aria-valuenow`。
- 已完成任务收进 `<details class="task-done">`：同一套任务行变灰、加删除线、
  显示完成日期与「已附凭证 / 自述完成 · 未附凭证」，补凭证入口保留。
- 窄屏（≤720px）操作按钮移到标题下方整行铺开；长标题在行内换行，
  编号不再单独占一行。

### 验证

- `TasksView.spec.js` 15 条通过：原有选择器与数据契约全部保留，新增
  「离场动画结束才刷新」「减少动态效果直接刷新」「进度条数值」「难度/周数只显示真有的」。
- 全量前端：**19 文件 / 129 条通过**；`npm run build` 成功。
- Chrome CDP + 临时 Vite（5174）+ 假接口（8001）验收：
  - 1440×1000 / 390×844 列表与已完成折叠正常，窄屏无横向溢出；
  - 点击「标记完成」后 80ms 截到该行划掉并淡出的中间帧，220ms 后仍在原位，
    400ms 后才从待办中移除；
  - 完成后待办 5→4、已完成 3→4、进度 38%→50%，已完成行全部 `line-through`；
  - 两种宽度控制台均 0 报错。验收后停止 5174/8001 并删除临时 Vite 配置。

### 风险

- 后端没有单条任务的「编辑 / 删除」接口，本次**不伪造按钮**，只保留
  「标记完成」「附凭证 / 心得」两个真实可用的操作。
- 完成后的任务仍保留在已完成折叠册里，这是刻意保留证据链；
  用户看到的是它从待办列表里「咻」地消失。
- 动画时长 400ms 与 `LEAVE_MS` 常量、CSS keyframes 三处同步维护，改动时需一起改。

## 阶段 8：结果改独立抽屉 + 学习路线/实战项目重排

### 改了什么

- **修掉点「标记完成」后页面上跳**：根因不是刷新，而是 `showCompletion()` 里对
  页面顶部的 `#tv-result` 调了 `scrollIntoView({ block: 'start' })`。任务行在中段，
  结果块在顶部，一滚就整页被拽回页首。补凭证分支的 `#tv-attach-result` 同样问题。
  两处 `scrollIntoView` 全部删除。
- **结果改为右侧独立抽屉**（`.reg-result-drawer`，Teleport 到 body）：
  提交结果和补凭证结果共用同一个抽屉，头部显示「第 N 轮 · 任务标题」，底部
  「收起结果」，点遮罩或 Esc 关闭。打开后焦点送到 `#tv-result`，用
  `focus({ preventScroll: true })`，不再滚页面；关闭后焦点回到当前页签。
- 为什么不做成第四个页签：结果是一次操作的即时回执，刷新或切走就该消失；
  做成路由页签会出现「空页签」和「结果归属哪条任务」的状态问题。抽屉承载瞬时结果，
  页签只留给可重复浏览的内容。如果以后确实需要「历史提交记录」再单独开页。
- **学习路线**从登记表列表改成纵向路线图：浅色渐变报头（第 N 轮 · 学习路线、
  「N 个阶段，按顺序推进」、阶段/预计周数/覆盖缺口三项读数）+ 一条
  「本轮岗位依据」快照条 + 带竖向轨道的阶段卡（编号圆点、阶段标签、主题、目标、
  覆盖缺口胶囊、前置阶段、薄荷底「完成标准」）。数据全部来自现有
  `learning_plan` 字段，没有新接口、没有编造字段。
- **实战项目**改成两列卡片墙：同样的渐变报头（项目/技术栈/覆盖缺口）+ 项目卡
  （编号、名称、难度/阶段标签、目标、技术栈、覆盖缺口、最终成果）；有
  `blocked_reason` 的项目左侧换成暖色警示轨并追加一条原因条。窄屏单列。
- 同步删除改版后不再使用的 `.reg-result-anchor` / `.reg-result-tools`；
  `.reg-app` 系列里只保留仍在用的说明与徽标规则，避免死样式。
- 抽屉眉标颜色从 `--text-faint` 提到 `--text-muted`，浅底上更易读。

### 验证

- `TasksView.spec.js` 16 条通过；新增「提交结果在独立抽屉里打开，不把页面滚回页首」：
  断言抽屉出现、`#tv-result` 在抽屉内、`scrollIntoView` **一次都没被调用**、
  点「收起结果」后抽屉消失。学习/项目子页断言改为读取 `.learn-route` / `.proj-grid`。
- 全量前端：**19 文件 / 130 条通过**；`npm run build` 成功
  （TasksView chunk 42.54 kB）。
- Chrome CDP + 临时 Vite（5174）+ 假接口（8001）独立假数据验收：
  - 移动端先把页面滚到 520，再点「标记完成」，抽屉打开后 scrollY 仍是 **520**；
    桌面端页面最大可滚距离只有 32，操作后停在 32（夹紧到底部，不是回到 0）。
  - 抽屉桌面宽 560、移动端整宽 390；`#tv-result` 获得焦点；关闭后抽屉卸载。
  - 学习路线 3 个阶段卡、实战项目 4 张卡；390px 下 `scrollWidth = 390`，无横向溢出；
    两种宽度控制台 0 报错。
  - 验收后停止 5174/8001、删除临时 Vite 配置并清掉残留进程。

### 风险
