# MySQL 求职档案：切换与回退

日期：2026-11-06

这次改造把账号、基础资料、求职档案、分析轮次、任务、成长记录收进六张表。
默认仍可用 SQLite（`runs/app.db`）；要换 MySQL，按下面的顺序做，**每一步都能回退**。

## 0. 先备份

```bash
# 停掉后端后，复制一份当前 SQLite
cp runs/app.db runs/app.db.bak-$(date +%Y%m%d%H%M%S)
```

旧单用户 JSON（`runs/loop.json`、`runs/growth.json`）如果还在，原样保留；
新版不会自动认领、也不会改写或删除它们。

## 1. 建库与最小权限账号

```sql
CREATE DATABASE career_agent CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'career_app'@'127.0.0.1' IDENTIFIED BY '<强密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES
  ON career_agent.* TO 'career_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

应用只需要在此库内建表与增删改查，不需要 `DROP` 或全局权限。

## 2. 设置连接串并建表

`CAREER_DB_URL` 走进程环境变量；不要把密码写进仓库或 `.env` 提交。

```bash
export CAREER_DB_URL='mysql+pymysql://career_app:<强密码>@127.0.0.1:3306/career_agent?charset=utf8mb4'
.venv/Scripts/python.exe -m backend.db --init
```

成功输出为「数据库结构已就绪（mysql）」；重复执行安全（幂等）。
驱动依赖已固定在 `requirements.txt`（`PyMySQL==1.1.3`）。

## 3. 迁移账号

**账号迁移没有内置脚本**，因为旧库只在本机。两种做法任选：

- 保留 SQLite 作为账号来源不现实（应用只连一个库），推荐在 MySQL 重新注册账号；
- 如必须保留旧账号，手工导出 `users` 行并插入 MySQL（`id`/`username`/`password_hash` 原样保留，`created_at` 转 UTC），或在停服窗口写一次性小脚本。

注册后账号密码哈希仍可直接使用；JWT 密钥如果沿用原来的 `runs/jwt_secret.key`，已登录用户无需重新登录。

## 4. 导入旧业务数据（可选，显式两步）

```bash
# 先只读盘点，不写库
.venv/Scripts/python.exe scripts/migrate_legacy_plans.py --user <用户名或用户 id>

# 确认盘点结果（文件哈希、轮次/任务/成长计数、归属提示）后，
# 备份并写入一份 legacy_readonly 档案
.venv/Scripts/python.exe scripts/migrate_legacy_plans.py \
  --user <用户名或用户 id> --apply --confirm
```

约束：

- 缺归属字段、或文件名 `user_<id>` 与 `--user` 不一致时拒绝执行，**不猜**；
- 同账号多个岗位不自动拆分，作为一份只读档案导入；
- 重复执行不重复导入；已删除的迁入档案不会复活（除非显式 `--reimport`）；
- 导入前自动复制到 `legacy-backups/<UTC 时间>/` 并校验 SHA-256，校验不符即中止。

## 5. 启动与验收

```bash
.venv/Scripts/python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --workers 1
```

验收清单：

1. 注册/登录 → 创建 A、B 两份档案；
2. 在 A 提交一条成果，B 的待处理列表应为空；
3. A→B→A 切换，URL 带 `?plan=`，刷新后仍是同一份；
4. 删除 A：A 的分析/任务/成长 404，B 与账号基础资料仍在；
5. 删除最后一份：页面进入空态，基础资料保留；
6. 重新登录：仍能看到剩下的档案。

## 6. 回退

1. 停服务；
2. 去掉 `CAREER_DB_URL`（或指回原 SQLite）；
3. 恢复备份的 `runs/app.db`；
4. 启动旧版本。

注意：

- 新版只写六张表，不写 `runs/users/*` JSON；回退前不要删除旧 JSON 原件；
- 在 MySQL 期间新增的档案不会出现在旧库中，回退会“丢”这部分新数据 —— 需要保留时先导出；
- 不要在回退后继续指向 MySQL 又删除 SQLite 备份，两份库不能同时被写。
